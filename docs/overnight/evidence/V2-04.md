## Changes
1. **`GapSystem` (`src/game/systems/GapSystem.ts` [NEW]):**
   - Tracks `gap = villain.rig.x - chaser.rig.x` in logical pixels.
   - Zones strictly classified:
     - `CLOSE`: `gap < 220` (melee allowed, hits get +25% damage bonus, camera shake, and patience restoration).
     - `MID`: `220 <= gap <= 560` (chappal and projectile range, melee out of range).
     - `FAR`: `560 < gap < 900` (villain gaining, patience slowly drains at 1.5/sec).
     - `ESCAPE`: `gap >= 900` (warning state; if sustained for 6 continuous seconds, triggers Lose result with `"escaped"`).
   - Method `isMeleeInRange(): boolean`: requires `currentGap <= 220` AND `Math.abs(chaserLane - villainLane) <= 1`.
   - Methods `reduceGap(amount)` and `widenGap(amount)`: adjusts gap dynamically (e.g. dash closes gap by +160px; projectile hits close gap by +30..40px; taunt stumble closes gap by +80px).
   - Dynamically slides entities within fixed arena window `[120, 1160]` centered at 590:
     - `chaserHome = max(120, 590 - gap/2)`
     - `villainHome = min(1160, 590 + gap/2)`
   - Speed differential updates gap based on relative run speeds (`effectiveVillainSpeed - effectiveChaserSpeed`).

2. **Zustand Store API (`src/store/useGameStore.ts`):**
   - Added state fields:
     - `patience: number` (0..100, default 100).
     - `chaserSpeedMultiplier: number` (default 1.0).
     - `gap: number` (default 560).
     - `gapZone: "CLOSE" | "MID" | "FAR" | "ESCAPE"` (default "MID").
     - `failReason: "escaped" | "patience_zero" | null` (default null).
   - Added actions:
     - `drainPatience(amount: number)`: drains patience; if `<= 0`, clamps to 0 and triggers fail state `triggerLose("patience_zero")`.
     - `restorePatience(amount: number)`: increases patience clamped to 100.
     - `slowChaser(mult: number, durationSec: number)`: applies multiplier to `chaserSpeedMultiplier` and restores to 1.0 after duration.
     - `setGap(gap: number, zone?: GapZone)`: updates gap and zone.
     - `triggerLose(reason: "escaped" | "patience_zero")`: sets `screen: "GAME_OVER"`, sets `failReason`, and emits `"game:lose"` on `gameBus`.
   - Updated `resetRun()` and `startGame()` to reset patience, gap, and failReason.

3. **Combat Melee Range & Mashing Penalty (`src/game/systems/CombatSystem.ts`):**
   - Injected `gapSystem` into `CombatSystem`.
   - Melee attacks (`slap`, `punch`, `kick`) check `this.gapSystem.isMeleeInRange()`:
     - **If out of range:** Attack misses! Plays whoosh/miss sound, displays floating miss text ("মিস! / অনেক দূর! / কাছে যান!"), drains 4 patience (`store.drainPatience(4)`), and resets combo. A mashing-only player who mashes attacks without dashing quickly runs out of patience and loses!
     - **If in range:** Connects! In `CLOSE` zone (`gap < 220`), applies +25% damage bonus, camera shake, and restores +4 patience.
   - Projectile attacks (`chappal`, `banana`, `can-kick`): connect from range, deal damage, stumble the villain, reduce the gap by +30..40px, and restore patience.
   - Ultimate (`Chappal Storm`): closes gap by +100px and restores +10 patience.

4. **Game Loop & Test Hook Wiring (`src/game/scenes/RunScene.ts`, `src/game/testHook.ts`):**
   - Attached `GapSystem` to `RunScene`: updated every frame with `clampedDelta`.
   - Dash command (`DASH`) calls `this.gapSystem.reduceGap(160)`.
   - `testHook.ts` registered state providers:
     - `getState().gap`: live numeric gap.
     - `getState().patience`: live patience value (0..100).
   - Registered debug handlers:
     - `window.__game.debug.call("setGap", gap)`
     - `window.__game.debug.call("drainPatience", n)`
     - `window.__game.debug.call("slowChaser", mult, sec)`

5. **UI & Fail Screens (`src/components/game/HudOverlay.tsx`, `GameOverScreen.tsx`, `AppShell.tsx`):**
   - `HudOverlay.tsx`: added sweat-drop Patience bar (`💧 PATIENCE (ধৈর্য) XX%`), color-coded (cyan > 50%, amber 25-50%, red <= 25%), and gap warning banners for `FAR` and `ESCAPE` zones with live distance in px.
   - `GameOverScreen.tsx`: displays `"OUT OF PATIENCE!"` (`"হাল ছেড়ে দিলে?!"`) on patience-zero loss, and `"TARGET ESCAPED!"` (`"পালাইছে!"`) on escape loss.
   - `AppShell.tsx`: unified `PLAYING`, `PAUSED`, and `GAME_OVER` container so `GameHost` is kept continuously mounted without destroying the Phaser WebGL context.
